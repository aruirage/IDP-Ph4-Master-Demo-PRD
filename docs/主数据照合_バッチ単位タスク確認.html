案件・バッチ・補件の取扱い確認

対象：IDP 案件サービス／主データ照合 API　｜　2026-11-20
1バッチを1つの IDP タスクとして扱い、新しいバッチまたは補件が届いた場合は新しいタスクを追加します。
Zurich へ送る内容は、その時点の案件に含まれる全有効書類です。

運用案

案件は1つ案件番号と有効書類の一覧を保持します。
1バッチ＝1タスク初回、追加、補件をそれぞれ別タスクとして記録します。
全有効書類を送信各タスクで、その時点の案件全体を API に渡します。
最新バッチを優先古いタスクの遅延結果は履歴に残し、最新結果を上書きしません。

図1　案件、バッチ、補件の関係

新しく追加されたタスク 案件に保持される既存タスク バッチは IDP の管理単位です。API の処理単位は案件スナップショットです。

図2　遅れて返ってきた結果の扱い

IDP側で保持する対応情報

batchTaskId
1バッチごとの IDP タスク。一覧と待ち件数の単位。
batchSeq
案件内の受信順。古い結果を判別するために使用。
clientRequestId
案件番号、バッチ順、分割番号を含む API の冪等キー。
apiTaskIds
Zurich の taskId。通常1件、50書類超では複数。
lastAppliedBatchSeq
案件の現在値に最後に反映したバッチ順。
affectedItems
補件により再確認・再反映が必要になった項目。

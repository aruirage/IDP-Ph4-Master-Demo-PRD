# 主数据照合 API｜规格与真实场景差异说明

## 已确认的接口规则

- 每个案件提交当时有效的全部账票。
- 每次请求最多 50 件逻辑账票。规格书 Q-01 原文要求超过 50 件时拆分；IDP 第四期决定超过 50 件时默认失败、不创建 Task，拆分部分列入第 2 期候选范围。
- 请求进入 Zurich 队列。同一优先级按受理顺序处理，并发数量由 Zurich 控制。
- `priority=NORMAL` 为普通处理，`LOW` 在没有等待中的 `NORMAL` 时处理。
- `items/standardize` 单个值重新照合按 C-03 原文列入本期。

## IDP 已定的批次处理

- 新文件到达时创建新的独立批次任务。
- 补件到达时同样创建新的独立批次任务。
- 每个独立批次任务的结果分别进入 OCR抽出确认。
- 超过 50 件的业务批次本期直接失败，不拆成多个 Zurich 任务，也不合并多个 `taskId`。
- 旧任务结果晚到时，只更新该任务自己的结果和待办，不修改其他任务。
- IDP 不另建案件级队列，沿用 Zurich 的同一优先级受理顺序。

## 结论

规格书已定义排队、优先级、请求拆分和配置校验的 API 行为。IDP 第四期将超过 50 件默认失败，超限拆分延期至第 2 期候选范围。各环境的流量与并发具体值、任务结果准确保留天数仍需 Zurich 提供并确认。
